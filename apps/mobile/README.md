# style.id mobile

Expo (React Native, TypeScript, expo-router) iPhone app. Answers "will this exact top fit me, and where will it be tight or loose?" with per-zone ease in centimetres against a tee you measured yourself.

Expo SDK 58 · React Native 0.88 · pnpm.

## Prerequisites

- Node 20+ and pnpm (`corepack enable` or `npm i -g pnpm`).
- An [Expo account](https://expo.dev) and the EAS CLI (`pnpm dlx eas-cli login`).
- An Apple Developer account (paid) for device builds, Sign in with Apple and the share extension.
- For local iOS builds only: a Mac with Xcode 16+. Linux/Windows can run the unit tests, typecheck and lint, and start the Metro bundler for a dev build installed on a phone.

## Everyday commands

```bash
pnpm install
pnpm typecheck && pnpm lint && pnpm test   # the CI gate
pnpm start                                 # Metro for an installed dev build (expo start --dev-client)
pnpm ios                                   # expo run:ios (Mac + Xcode only)
pnpm gen:api                               # regenerate src/api/types.gen.ts from openapi.json
```

## Why Expo Go does not work

Three things in this app need native code that is not in Expo Go:

- `modules/ar-capture`: ARKit (floor-plane scale for flat-lay measuring, LiDAR `sceneDepth` body-scan keyframes).
- `modules/vision-masks`: Apple Vision (foreground mask of the garment, person segmentation, body pose).
- `expo-share-intent`: the iOS share extension that receives product URLs from Safari and shop apps.

Plus `@shopify/react-native-skia`, `expo-gl` and `expo-apple-authentication`, which also need a custom build. Use an **EAS development build** (`expo-dev-client` is installed) and then `pnpm start`.

On Android, the simulator, or any build without the native modules, the capture and LiDAR screens show a "needs an iPhone build" message and everything else (manual entry, product checks, fit reports, outcomes) still works.

## Creating a development build

```bash
pnpm dlx eas-cli init          # once: links the project; writes EAS_PROJECT_ID into your env / app.config extra
pnpm build:dev                 # eas build --profile development --platform ios
```

`eas.json` has three profiles: `development` (dev client, internal distribution), `preview` (internal), `production`. Register your iPhone's UDID when EAS asks (`eas device:create`), install the build from the link, open it, then run `pnpm start` and scan the QR code.

Do not run `expo prebuild` by hand and commit the result; `ios/` and `android/` are generated by EAS from `app.config.ts` and the config plugins.

## Backend URL

The API base URL is `EXPO_PUBLIC_API_URL` (default `http://localhost:8000`, see `/.env.example` at the repo root). Set it per build profile in `eas.json` (`build.<profile>.env`) or export it before `pnpm start`:

```bash
EXPO_PUBLIC_API_URL=http://192.168.1.20:8000 pnpm start   # phone on the same Wi-Fi as the FastAPI server
```

In `__DEV__` builds with no Apple JWT, requests carry `X-Dev-User: <handle>` from the developer sign-in field on the sign-in screen. Production builds only send `Authorization: Bearer <jwt>` from `POST /v1/auth/apple`.

## API types

`src/api/types.gen.ts` is generated from the FastAPI service's OpenAPI document and is the single source of truth for request/response shapes. Regenerate after any API change:

```bash
# from the repo root: export the document, then generate the TypeScript
uv run python -m styleid_api.openapi > apps/mobile/openapi.json
cd apps/mobile && pnpm gen:api     # openapi-typescript openapi.json -o src/api/types.gen.ts
```

Do not edit `openapi.json` or `types.gen.ts` by hand. `src/api/schema.ts` re-exports the generated schemas under app-friendly names (`Garment = ClosetGarmentOut`, `FitReport = FitReportOut`, `BodyRecord = BodyRecordOut`, ...) and keeps the enum constant arrays (`ZONES`, `LABELS`, `GARMENT_FIELDS`, ...) that drive pickers; it is the only import site for domain types. `src/api/client.ts` is an `openapi-fetch` client typed with the generated `paths`, so a wrong path or body fails `pnpm typecheck`.

## The two native modules

Both live in `apps/mobile/modules/` and are picked up by Expo autolinking by directory convention (`expo-modules-autolinking` searches `./modules` by default, see the `nativeModulesDir` option). Each has an `expo-module.config.json` naming its Swift module class, a podspec, a `package.json`, a typed `index.ts` that resolves to rejecting stubs when the module is missing or the platform is not iOS, and an `app.plugin.js` referenced from `app.config.ts` that only adds Info.plist entries. Verify with:

```bash
node node_modules/expo-modules-autolinking/bin/expo-modules-autolinking.js resolve --platform apple --json
```

### `ar-capture` (`modules/ar-capture/ios/*.swift`)

- `isLidarAvailable()`: `ARWorldTrackingConfiguration.supportsFrameSemantics(.sceneDepth)`.
- `<ArCaptureView mode="flatlay" />`: ARSCNView with horizontal plane detection. Emits `onPlaneDetected { distanceM, cmPerPixel, extentM }` once a floor/table plane is tracked. Scale is `distance / fx` from the camera intrinsics.
- `captureFlatLay()`: grabs the current frame, rotates it to portrait, saves a JPEG and returns `{ imageUri, imageWidth, imageHeight, cmPerPixel, intrinsics: [fx, fy, cx, cy], planeDistanceM }`.
- `<ArCaptureView mode="body" />` + `startBodyScan({ keyframes })` / `stopScan()`: `sceneDepth` frame semantics, one keyframe per yaw bucket across a full turn (40 by default), only `.high` confidence depth kept. Writes `kf_NNN.jpg`, `kf_NNN_depth.png` (uint16 millimetres), `kf_NNN_conf.png`, and `manifest.json` (intrinsics, camera transform, yaw, timestamps) into a temp directory and returns `{ directoryPath, keyframeCount }`. Upload of that directory to the body-fit worker is the next step and not wired yet.

### `vision-masks` (`modules/vision-masks/ios/VisionMasksModule.swift`)

- `foregroundMask(imageUri)`: `VNGenerateForegroundInstanceMaskRequest` (iOS 17+) → PNG mask + the largest contour (`VNDetectContoursRequest`, simplified to ≤ 200 points, normalised, top-left origin).
- `personSegmentation(imageUri)`: `VNGeneratePersonSegmentationRequest` → PNG mask.
- `bodyPose(imageUri)`: `VNDetectHumanBodyPoseRequest` → `{ points: { jointName: [x, y, confidence] } }`.

The Swift sources compile in EAS Build (Xcode); they cannot be compiled or exercised on Linux. The pure parts of the capture flow (`src/capture/geometry.ts`: cm-per-pixel, landmark proposal from a silhouette, measurements from landmarks) and the report wording (`src/fit/format.ts`) are unit-tested with Jest.

## Layout

```
app/                 expo-router routes: (auth)/sign-in, (tabs)/{closet,check,body}, closet/{new,capture,[id]},
                     check/[reportId], outcomes/[reportId], body/{scan,photo,manual,confirm}, avatar/[reportId]
src/api              openapi-fetch client, hand-written schema types, react-query hooks
src/capture          flat-lay geometry (tested)
src/fit              report formatting (tested)
src/components       small plain components (Skia landmark overlay, field guides, three.js avatar, ...)
src/store            zustand stores (auth token in SecureStore, body-record draft)
modules/ar-capture   Swift Expo Module: ARKit
modules/vision-masks Swift Expo Module: Vision
```
