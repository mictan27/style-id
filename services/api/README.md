# styleid-api

FastAPI server behind the style.id iPhone app: auth, closet, body records, products and
size charts, fit reports, purchase outcomes. The fit maths lives in `styleid_fit`; the
shared Pydantic vocabulary in `styleid_schema`; chart extraction in `styleid_charts`.

## Run locally

```bash
uv sync --all-packages
uv run alembic -c services/api/alembic.ini upgrade head      # creates ./styleid-dev.db
uv run uvicorn styleid_api.main:app --reload                 # http://localhost:8000/docs
```

With no configuration the server uses SQLite (`./styleid-dev.db`), dev auth is on, and
chart extraction runs inline in the request. Set `STYLEID_AUTO_CREATE_TABLES=true` to
skip the migration step on a throwaway SQLite file.

```bash
curl -H 'X-Dev-User: alice' localhost:8000/v1/me
curl -H 'X-Dev-User: alice' -X PATCH localhost:8000/v1/me -d '{"dob_verified_18": true}' -H 'content-type: application/json'
curl -H 'X-Dev-User: alice' -X POST localhost:8000/v1/products/check -d '{"url": "https://shop.example.com/products/tee"}' -H 'content-type: application/json'
```

## Environment

All settings are read with the `STYLEID_` prefix (see `styleid_api/config.py`). The
variables that `.env.example` lists un-prefixed are accepted in both spellings; the
prefixed one wins.

| Variable | Default | Notes |
|---|---|---|
| `DATABASE_URL` / `STYLEID_DATABASE_URL` | `sqlite+pysqlite:///./styleid-dev.db` | Postgres: `postgresql+psycopg://user:pw@host:5432/styleid` |
| `STYLEID_AUTO_CREATE_TABLES` | `false` | `create_all` at startup; SQLite dev only |
| `STYLEID_DEV_AUTH_ENABLED` | `true` | **Set `false` in production.** |
| `STYLEID_DEV_AUTH_SECRET` | unset | When set, dev auth also requires `X-Dev-Secret` |
| `STYLEID_APPLE_CLIENT_ID` | `id.style.app` | iOS bundle id; the `aud` of Apple identity tokens |
| `STYLEID_APPLE_JWKS_URL` | `https://appleid.apple.com/auth/keys` | Cached for `STYLEID_APPLE_JWKS_TTL_SECONDS` (3600) |
| `STYLEID_JWT_SECRET` | insecure dev value | HS256 secret for our bearer tokens. **Set in production.** |
| `STYLEID_JWT_TTL_SECONDS` | 30 days | |
| `ANTHROPIC_API_KEY` / `STYLEID_ANTHROPIC_API_KEY` | unset | Used by `styleid_charts` |
| `CHART_EXTRACTION_MODEL` / `STYLEID_CHART_EXTRACTION_MODEL` | `claude-opus-5-5` | Passed to the chart extractor |
| `BLOB_BUCKET` / `STYLEID_BLOB_BUCKET` | `styleid-dev` | Mesh and photo blobs (keys only are stored here) |
| `STYLEID_EXTRACTION_RUNNER` | `inline` | `inline` or `queue` (see below) |

## Auth

Two paths, both end in `get_current_user` (`styleid_api/auth/deps.py`):

* **Dev auth** (only when `STYLEID_DEV_AUTH_ENABLED=true`): send `X-Dev-User: <handle>`.
  The user is created on first use with `apple_sub = dev:<handle>`.
* **Sign in with Apple**: `POST /v1/auth/apple` with `{"identity_token": "...",
  "dob_verified_18": true}`. The token's signature is checked against Apple's JWKS
  (`kid` lookup, one forced refresh on an unknown key), plus `iss`, `aud` and `exp`.
  The response is our own HS256 JWT; send it as `Authorization: Bearer <token>`.

Endpoints that store body data (`POST /v1/body/records`, `.../confirm`) return **403**
until the user has `dob_verified_18` (set through Apple sign-in or `PATCH /v1/me`).

## Migrations

```bash
uv run alembic -c services/api/alembic.ini upgrade head
uv run alembic -c services/api/alembic.ini revision --autogenerate -m "describe change"
uv run alembic -c services/api/alembic.ini check          # models vs database drift
uv run alembic -c services/api/alembic.ini -x url=sqlite+pysqlite:///tmp.db upgrade head
```

The URL comes from `-x url=...`, else `sqlalchemy.url` (when set programmatically), else
`Settings.database_url`. Migrations are generated with `render_as_batch` so they run on
SQLite as well as Postgres. The `products.chart_id -> size_charts.id` foreign key is a
cycle with `size_charts.product_id`; it is added after both tables exist
(`use_alter=True` on the model, a separate `create_foreign_key` in the revision).
Always read an autogenerated revision before committing it.

## Chart extraction runner

`POST /v1/products/check` creates a `size_charts` row in `pending` and hands its id to
the configured `ExtractionRunner` (`styleid_api/jobs/extraction.py`):

* `inline` (default): `InlineRunner` runs `process_size_chart` synchronously in the
  request; the response already carries the final chart status. Used in dev and tests
  (tests inject a fake `extract_fn`).
* `queue`: `QueueRunner` defers a procrastinate job (`styleid_api.jobs.extraction.extract_size_chart`,
  queue `extraction`) on the Postgres database. Run the worker with
  `uv run procrastinate --app styleid_api.jobs.worker.app worker --queues extraction`
  and apply procrastinate's own schema once (`uv run procrastinate --app ... schema --apply`).
  The response then shows `chart.status == "pending"`; poll `GET /v1/products/{id}`.

The only contract with `styleid_charts` is `ExtractFn = (url, garment_kind) -> NormalisedChart`.
The production implementation (`default_extract`) imports `styleid_charts` lazily and
wraps `pipeline.extract_product` with an `HttpxFetcher` and a `ClaudeExtractor`; an
import or signature mismatch becomes a `failed` chart with the reason in `error`.
When a chart finishes `ok`, one `garments` row per size is written with `product_id` +
`size_label`, and the product's `chart_id`, `stretch_class`, `cut` and
`fabric_composition` are filled in. `POST /v1/fit/reports` returns 409 until that has
happened.

## OpenAPI

```bash
uv run python -m styleid_api.openapi > openapi.json
```

Every operation has a stable camelCase `operationId` derived from the handler name
(`listClosetGarments`, `createFitReport`, ...) and a tag per router; the mobile app
generates its TypeScript client from this document.

## Tests and checks

```bash
uv run pytest services/api -q
uv run ruff check services/api && uv run ruff format --check services/api
uv run mypy services/api/src
```

Tests run on SQLite in a temporary directory with dev auth, a fake extractor and a
locally generated RSA key standing in for Apple's JWKS. Postgres, procrastinate and the
live Apple endpoint are not exercised locally.
