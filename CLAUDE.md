# style.id — notes for agents

Measurement-based fit app for tops. Python uv workspace (fit engine, schema, chart extraction, body fit, calibration, FastAPI API, worker) plus an Expo iPhone app in `apps/mobile`. Read `README.md` for layout and `docs/adr/0001-stack.md` for decisions.

## Check your work (run before saying something is done)

```bash
export PATH="$HOME/.local/bin:$PATH"     # uv lives here on the dev box
uv run pytest -q
uv run ruff check . && uv run ruff format --check .
uv run mypy packages/*/src services/*/src

cd apps/mobile
pnpm typecheck && pnpm lint && pnpm test     # tsc, eslint, jest (logic + screen render tests)
pnpm screenshots                             # Playwright: one PNG per screen in apps/mobile/screenshots/
```

**Look at the PNGs after any UI change** (open them with the Read tool); passing tests do not mean a screen looks right. Screenshots use Expo's web dev server (`pnpm web`, port 8099; leave it running to make reruns take seconds) and the same fixtures as the Jest screen tests. The web build has real layout, copy, data and the three.js fit map; ARKit, Vision and the Skia landmark overlay are iPhone-only, so those screens show their "needs an iPhone" state. When you add a screen, add it to `apps/mobile/e2e/screens.spec.ts` with a text it must show.

Native-only components get a `.web.tsx` sibling (`FieldGuide`, `LandmarkOverlay`, `BodyAvatar`); keep shared logic in a platform-neutral module next to them.

## Rules

- **Units are cm** everywhere in code and UI. Inches exist only inside chart extraction, which converts them.
- **The fit engine (`packages/fitengine`) is stdlib only** and imports nothing from services. Thresholds live in `thresholds.py`; changing one means updating golden cases in `tests/golden/` deliberately, not to make a test pass.
- **API contract changes** go in this order: edit the FastAPI routes or schemas, then regenerate. Never hand-edit `apps/mobile/openapi.json` or `apps/mobile/src/api/types.gen.ts`.
  ```bash
  uv run python -m styleid_api.openapi > apps/mobile/openapi.json
  uv run python services/api/scripts/export_mobile_fixtures.py   # screen-test + screenshot data
  cd apps/mobile && pnpm gen:api && pnpm typecheck && pnpm test
  ```
  CI fails if any of these generated files are stale.
- **Screen tests** (`apps/mobile/src/__tests__/screens.test.tsx`) render the real expo-router app against `src/test/fakeApi.ts`, which serves the exported fixtures. Override a route with `fakeApi().set(...)` for empty and error states. In this Testing Library version `fireEvent` and `cleanup` return promises: always `await` them, and re-query an element after state changes instead of holding a reference.
- **Schema JSON** in `packages/schema/json/` is generated by `packages/schema/scripts/export_json_schema.py`; CI diffs it.
- **Migrations**: autogenerate with Alembic, then read and fix the revision by hand. They must run on SQLite and Postgres.
- **Mobile domain types** are imported from `src/api/schema.ts` only.
- **Native code**: keep `modules/ar-capture` and `modules/vision-masks` thin; put maths in `src/capture/geometry.ts` where Jest can test it. Their `index.ts` must keep resolving to rejecting stubs off iOS so the web build and tests keep working.
- **Do not run `expo prebuild`** and commit `ios/` or `android/`. EAS generates them.
- **Expo Go cannot run this app.** iOS needs an EAS dev build (`pnpm build:dev`).
- **Raw body scans are deleted after processing.** Do not add code paths that keep them.
- Never print or commit `ANTHROPIC_API_KEY` or other secrets. Live Claude calls only run when the key is set; tests use recorded fixtures.

## What cannot be verified on the Linux dev box

Swift compilation, ARKit/Vision behaviour, the share extension, Sign in with Apple, Postgres-only paths and procrastinate. Say so explicitly when a change touches these instead of claiming it works.
